## Known issues / constraints

- The workspace is not currently a Git repository.
- The project targets iOS 17.0 and Swift 6. Its configured bundle identifier is `com.anoushkawayangankar.AirCanvas`; the product owner must confirm its App ID ownership in the intended Apple Developer team/App Store Connect account.
- `Assets.xcassets` and an explicitly assigned `AppIcon` are present and compile in Release. Distribution signing and App Store/TestFlight work remain intentionally deferred by the user’s current Personal Team decision.
- Onboarding completion is the only UserDefaults value; project data is not stored there.
- A supported physical device is required to validate the camera prompt, live camera feed, tracking quality, interruption recovery, and real AR world tracking.
- Milestone 6 enables horizontal and vertical plane detection only. It intentionally does not enable environment texturing, scene reconstruction, frame semantics, collaboration, or persistence.
- The temporary placement marker has been removed from normal Canvas interaction so it cannot interfere with drawing; it is not drawing-domain or persisted data.
- Milestone 9 creates temporary tube segments only for an active stroke, then replaces them with one generated eight-sided tube mesh per completed stroke. Final render paths are capped at 1,024 points. This controls completed entity growth; Milestone 30 physically exercised renderer and large-canvas workloads without identifying a production-blocking issue.
- An active stroke remains bounded at 512 raw points. Fast or sharply changing 3D paths can still require visual tuning of the smoothing, interpolation, or tube-frame strategy after device testing.
- Brush controls use five opaque named palette colors and a 2–20 mm thickness range; arbitrary colors, transparency, and cross-launch brush-preference persistence are intentionally not implemented yet.
- Undo/redo records completed `addStroke`, `deleteStroke`, and snapshot-based `moveStroke` actions and retains the most recent 100 actions in memory. It does not persist selection state, style edits, or session history.
- Selection collision shapes are generated for finalized stroke meshes and have not yet received physical-device usability tuning for very thin strokes or dense overlapping geometry.
- Project files are UUID-keyed local JSON documents in Application Support, each optionally referencing a separately securely archived ARWorldMap. Local canvas creation, opening, renaming, duplication, confirmation-gated deletion, document-specific autosave, and runtime/history isolation are automated-verified. There is still no cloud sync, rendered thumbnail/camera-frame storage, autosave-history persistence, or general migration engine. Spatial restoration and multi-canvas switching require physical-device validation and may fail in changed or feature-poor environments.
- Simulator supports non-AR flows and automated tests but is not a valid AR-runtime validation environment; physical-device raycast and touch drawing validation are complete.
- Vision processes no more than 15 AR camera frames per second and drops frames while a request is active. Milestone 30 physically validated the bounded scheduler and thermal/Low Power policy qualitatively; no raw camera frame, hand image, or landmark is persisted or uploaded.
- Hand drawing is gated by a confirmed pinch, a valid stabilized world-space fingertip, normal AR tracking, Draw mode, and relocalization readiness. Missing initial spatial input requires release and a new pinch; tracking, hand, mode, relocalization, and lifecycle loss cancel any active hand stroke. The complete core hand-drawing pipeline has been validated on a real iPhone.
- Hand stroke manipulation uses a 0.08-metre initial spatial hit radius and a root-entity translation preview. Deterministic tests and real-iPhone validation cover hover forgiveness, overlap behavior, surface-loss recovery, repeated manipulation, and perceived movement latency.
- Hand-selected deletion uses the same explicit Delete UI and stable-ID document path as touch selection. Automated tests and real-iPhone validation cover hover-versus-selection semantics, zero-movement selection, exact delete undo/redo, move-then-delete ordering, stale IDs, non-destructive loss/reset paths, repeated operations, and persistence through relocalization.
- Stroke transformations use a centroid pivot, 0.25×–4× scale clamp, and Y-axis world rotation. Pure transformer tests and real-iPhone validation cover stable pivoting, geometry/style/identity preservation, preview, semantic history, repeated transforms without drift, renderer reuse, persistence through relocalization, and touch/hand regressions.
- The spatial eraser uses a centralized 0.10-metre initial radius and reuses the pure polyline hit tester. It is intentionally one-pinch-one-delete, not a continuous or hover-triggered eraser; physical-device validation is complete.
- My Canvases currently presents reliable metadata previews (name, modification date, and stroke count) instead of generated thumbnails. Canvas duplication copies the associated local spatial map into a new map file; it therefore remains intended for work in the same physical environment until a future placement workflow is introduced.
- Native `.aircanvas` transfer deliberately excludes ARWorldMap data. Imported artwork is translated from its exported centroid to a deterministic fresh-session reference and is not expected to relocalize to the sender’s room. The existing Select-mode translation workflow provides subsequent user positioning. PNG export uses an orthographic dominant-axis projection rather than live camera perspective; it is an artwork preview, not a spatial scene capture.
- Milestone 26 keeps one bounded validated backup beside every persisted canvas primary, using an envelope with storage version, revision, byte count, and checksum. A damaged primary can restore from the last valid backup; if both are invalid the damaged canvas is isolated without breaking My Canvases. The repository scans primary documents instead of relying on a separate fragile index, rejects stale revisions, preserves dirty in-memory work on write failure, and retries on demand. These safeguards reduce but cannot eliminate loss from force termination before an iOS background flush receives execution time, physical storage failure after process death, or simultaneous external file tampering.
- Milestone 27’s conservative performance policies were exercised during Milestone 30 physical validation. Vision remains capped at 15 Hz normally, 12 Hz under serious thermal pressure or Low Power Mode, and 8 Hz under critical pressure; these values protect responsiveness but are not universal battery, FPS, or thermal guarantees. Large-canvas workloads and sustained editing showed no production-blocking issue on the validated iPhone, while performance can still vary by device generation, document size, lighting, and iOS thermal control.

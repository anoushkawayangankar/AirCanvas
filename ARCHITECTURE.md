# AirCanvas Architecture

## Status

Milestone 13 adds local project persistence, autosave, project-library management, and domain-stroke reconstruction. It deliberately does not add AR world-map restoration or physical-room relocalization.

## Architectural principles

- SwiftUI owns presentation and renders observable feature state only.
- Feature and framework boundaries are explicit; views do not configure ARKit or manipulate RealityKit scenes.
- Dependencies are injected through narrow protocols or concrete services where that improves testing.
- Models used for persistence remain independent of RealityKit entities and Vision observations.
- Errors are represented, surfaced when actionable, and logged through OSLog without camera-image data.
- UI state is main-actor isolated. ARKit delegate adapters do minimal work and transfer typed Sendable events to the main actor.

## Current application structure

```text
AirCanvas/
  App/                 App entry point, root navigation, route model, app-level error state
  Core/
    Logging/           OSLog category definitions
    Permissions/       Typed camera authorization service
    Capabilities/      AirCanvas-specific AR world-tracking support check
    AR/                Session lifecycle, tracking state, raycasting, scene host, and RealityKit renderer
    Drawing/           Input-independent stroke lifecycle, processing, and pure tube geometry
    Persistence/       Atomic local project repository and autosave ordering coordinator
  Models/
    Drawing/           Persistent drawing-domain values and schema-versioned project model
  Features/
    Home/              Product entry screen
    Onboarding/        First-launch education and completion-state owner
    Canvas/            Canvas access flow, live AR host, brush controls, and feature lifecycle state
    Projects/          Persisted project-library feature state
    Settings/          Settings landing state
  Resources/           Target Info.plist
AirCanvasTests/        Unit tests for feature and state logic
AirCanvasUITests/      Onboarding and foundation-navigation UI tests
```

The target is iOS 17.0 with Swift 6 and strict concurrency checking enabled.

## Drawing-domain models and serialization

`Models/Drawing` contains only Foundation and simd-based values. It does not import ARKit, RealityKit, SwiftUI, Vision, or persistence frameworks. It is the source of truth for future project storage, rendering inputs, undo/redo values, selection/edit operations, and touch or hand drawing output.

`CanvasPoint3D` is the explicit codable representation for a spatial coordinate. It stores finite `Float` x/y/z values, rather than relying on an implicit SIMD encoding, and provides a small conversion boundary to and from `SIMD3<Float>`. `StrokePoint` holds one ordered `CanvasPoint3D` plus an optional finite, relative timestamp. Individual point identifiers are intentionally omitted: current and planned editing operates on strokes, while adding permanent per-point identities would add storage and migration cost before a concrete need exists.

`BrushColor` stores validated RGBA Float components in the closed 0...1 range. `BrushStyle` stores a color and a finite, positive thickness and is an immutable snapshot on each `Stroke`. This ensures a later color/thickness change cannot alter completed work. `BrushSettings.defaultSettings` centralizes the default opaque Sky color and 6-millimetre thickness. `BrushSettings` is mutable in-memory Canvas-session state, validates each update through `BrushStyle`, and is intentionally not project persistence data.

`Stroke` has a stable UUID, ordered points, immutable style snapshot, and creation date. It requires at least two points, so future input systems must represent in-progress gestures separately and create a `Stroke` only on completion. `CanvasTool` is a typed Codable enum with draw, select, and erase cases. The Canvas currently exposes only the implemented draw and select modes; erase remains unavailable until it has real behavior.

`CanvasProject` has stable UUID, normalized non-empty name, creation/modification dates, ordered strokes, optional spatial-state metadata, and a top-level `schemaVersion`. It rejects modification dates before creation, duplicate stroke UUIDs, and unsupported versions. Its initial version is `1`; the repository probes that version before decoding and provides the migration boundary for later schemas.

All persistent-domain decoders call their validating initializers. Invalid colors, thicknesses, coordinates, timestamps, completed strokes, project names, stroke identifiers, dates, and schema versions fail decoding rather than being silently clamped or repaired. This preserves corruption visibility for the future repository layer.

## Navigation, onboarding, and permissions

`AirCanvasApp` creates process-level `AppState` and `OnboardingState`. `RootView` synchronously routes first launch to onboarding, then owns one `NavigationStack` for Home destinations. `AppState` owns only typed navigation and the app-level recoverable error alert; it does not own Canvas, AR, or drawing state.

`OnboardingState` persists only the non-sensitive `AirCanvasOnboardingCompleted` Boolean in `UserDefaults`. It is not a project-data store.

Milestone 28 updates that store to a versioned first-run boundary (`AirCanvasOnboardingCompletionVersion` 2) while retaining legacy-completion compatibility. Its typed steps include welcome, interaction basics, camera education, real spatial preparation, and real hand check, followed by the later pinch and first-stroke stages. Permission and AR-world-tracking capability are injected behind the existing narrow services, so the camera request occurs only after the user chooses Continue on the privacy explanation. Returning from Settings refreshes the same typed permission state; unsupported Simulator/device state deliberately offers canvas-library access rather than pretending AR is available. The short tutorial uses native Dynamic-Type-safe text, labelled controls, text-plus-symbol status, and keeps touch editing as an accessible alternative. Settings can replay the education flow without touching persisted canvases.

For the interactive stages, onboarding does not own an AR session. `CanvasARExperience` remains the sole owner of the production `ARSessionService`, `HandTrackingCoordinator`, `CanvasARViewModel`, raycaster, and spatial cursor renderer. `CanvasRuntimeView` forwards the existing view model's `ARSessionState`, `HandTrackingState`, and accepted `SpatialFingertipState` to the small ARKit-free `SpatialReadinessState` bridge. This maps normal tracking to ready; initializing, excessive motion, insufficient features, relocalization, and unavailable tracking to concise guidance; interruptions and failures to non-completing states. Readiness is state-driven—not timer-driven. Hand check succeeds only when the production detector reports `.detected` and the shared cursor pipeline has accepted a tracked world position, so it cannot be satisfied by a raw or stale Vision observation. The real cursor continues to be rendered by the ordinary canvas runtime. Camera/lifecycle changes continue to use `CanvasARViewModel` cleanup and demand management; onboarding adds no AR/Vision loops. A persisted first-canvas ID prevents a resumed interactive onboarding session from creating duplicate initial canvases.

The subsequent pinch check is observation-only. `CanvasARViewModel` continues to own and run the same `PinchGestureClassifier` that normal hand drawing uses; it forwards only its semantic `.began`, `.ended`, and `.cancelled` events while the temporary `PinchVerificationState` is active. The check requires `.began` followed by `.ended`; a hold, an end without a begin, a tracking/hand loss, lifecycle reset, or permission loss cannot complete it. During this one onboarding stage, the view model suppresses draw/select/erase routing after the production classifier has emitted its semantic event, so gesture coaching cannot mutate the document, history, renderer, or autosave state. Try Again resets only the onboarding verifier; Skip bypasses coaching without modifying classifier configuration. Outside this scoped context, pinch routing is unchanged.

First-stroke coaching returns to the ordinary Draw-mode runtime. `CanvasARViewModel` exposes a narrowly scoped committed-stroke observer after the existing hand-stroke end path has finalized the renderer, recorded normal history, and called `documentDidChange`; onboarding completes only when that observer identifies its persisted onboarding canvas UUID. Thus the tutorial stroke uses the same `DrawingInputSource`, `DrawingEngine`, `Stroke`, history, revision, autosave, and recovery paths as normal user content. `OnboardingSpatialRuntimeView` persists only the initial canvas UUID in `UserDefaults`: it reloads that canvas after interruption; if none is recorded it reuses an existing repository canvas, or creates one `My First Canvas` only when the library is empty. Skipping first-stroke coaching cancels any active production stroke and creates no synthetic content. Replay follows the same stored-ID/reuse policy and never creates a new canvas solely for help.

Real-iPhone validation passed for the complete production first-run path: first launch → onboarding → contextual permission → production AR readiness → production hand tracking → accepted spatial fingertip/cursor → production pinch classifier → production `DrawingEngine` → committed `Stroke` → `CanvasProject` → normal autosave/persistence → normal editor. The onboarding implementation deliberately has no second `ARSession`, Vision pipeline, pinch classifier, drawing engine, or fake Stroke model. Validation also confirmed safe hand/tracking/permission/lifecycle loss handling, one-canvas creation, replay safety, and existing hand/touch editing regressions.

`SpatialCanvasAccessViewModel` owns the canvas-entry decision. It checks the existing capability service, then the existing camera-permission service, requests access only when not determined, and presents one of the following feature states: unsupported device, permission required, permission restricted, or ready for the live Canvas. It rechecks authorization when the scene becomes active, including while the live Canvas is visible, so a permission revoked in Settings returns to the permission-required state instead of attempting to continue AR.

## AR runtime and RealityKit ownership

`ARSessionService` is the sole owner of the `ARSession` lifecycle. It creates the session, is its delegate, creates the `ARWorldTrackingConfiguration`, and is the only component that calls `run`, `pause`, or reset/restart operations. The configuration enables horizontal and vertical plane detection because Milestone 6 uses existing-plane geometry for spatial raycasts. It does not enable environment texturing, scene reconstruction, frame semantics, collaboration, or other advanced features.

`RealityKitSceneController` owns one stable `ARView` for the active Canvas feature lifetime. It creates `ARView` with `automaticallyConfigureSession: false`, attaches the session created by `ARSessionService`, and has no session configuration, delegate, gesture, drawing, or persistence responsibility. Its `UIViewRepresentable` is a host only; SwiftUI updates never recreate the AR view or run the session.

`CanvasARExperience`, held in `@State`, keeps the session service, scene controller, and `CanvasARViewModel` together for one Canvas identity. This prevents a SwiftUI value-view recreation from pairing a retained view model with a different session or AR view. The feature view model keeps a weak-capturing event handler, avoiding a service/view-model retain cycle.

```text
SpatialCanvasAccessView
  -> LiveARCanvasView / CanvasARViewModel
    -> ARSessionService (session lifecycle and delegate)
    -> RealityKitSceneController (stable ARView host)
      -> ARKit ARSession + RealityKit ARView
```

## Raycasting and coordinate flow

`SpatialRaycastService` is the only component that translates an ARView screen-space point into a world-space result. It is created for the stable ARView but has no marker, drawing, gesture, or persistence responsibility. The service tries one deliberately ordered strategy:

1. `.existingPlaneGeometry` with any alignment, using ARKit's detected horizontal/vertical plane geometry.
2. `.estimatedPlane` with any alignment only when no existing-plane result is available.

`SpatialRaycastResult` is runtime-only and stores the world transform, its translation as `SIMD3<Float>`, and whether the result came from existing geometry or an estimated plane. It does not retain `ARRaycastResult`, `ARAnchor`, or any other framework object, so future touch drawing, fingertip cursor, selection, and editing can consume a stable application-facing coordinate.

```text
UIPanGestureRecognizer location in ARView coordinates
    -> CanvasTouchInputAdapter
        -> CanvasARViewModel (tracking eligibility and feature feedback)
            -> SpatialRaycastService.raycast(screenPoint)
                -> SpatialRaycastResult (world transform and world position)
                    -> CanvasPoint3D / StrokePoint
                        -> DrawingEngine and StrokeRendering
```

The pan recognizer is attached once by `CanvasTouchInputAdapter` in the ARView representable coordinator when the stable view is made; SwiftUI updates never add recognizers. It translates UIKit begin/change/end/cancel gesture states and the ARView-local point into a narrow input protocol. No normalized-coordinate conversion is used in this milestone: UIKit view coordinates are passed directly to `ARView.raycast`, and the returned AR world transform is converted only by reading its translation column. Future Vision integration must explicitly transform camera-image normalized coordinates into ARView coordinates before using this same service.

`CanvasARViewModel` permits raycasting only while the typed session state is running with normal tracking. Initializing, limited, unavailable, interrupted, failed, and idle states do not call ARKit raycasting; they preserve existing product guidance or show a concise placement hint. A normal tracking state or successful placement clears the non-intrusive hint.

Milestone 6's temporary placement marker is no longer part of the production Canvas interaction, so a drawing sample never creates a validation marker. It remains neither domain data nor persisted content.

## Touch drawing, stroke processing, and rendering

`DrawingEngine` in `Core/Drawing` is the input-independent source of truth for an active stroke and its completed `[Stroke]` values during one Canvas feature lifetime. It accepts only world-space `CanvasPoint3D` values, a `BrushStyle`, and a monotonic input timestamp. It has no ARKit, RealityKit, UIKit, SwiftUI, Vision, camera-permission, or gesture dependency. Touch is one client of this engine; a later fingertip/pinch input adapter will use the same begin/append/end/cancel API.

Beginning a stroke snapshots `BrushSettings.style`, preserving the style on that stroke even after future brush changes. The engine appends a point only when it is at least the explicit `DrawingEngineConfiguration.standard.minimumPointSpacing` of 0.01 metres from the previous accepted point. It caps one active stroke at 512 points as a temporary memory/rendering safety bound. A completed `Stroke` requires at least two accepted points; a tap, a no-result initial raycast, or an otherwise inadequate gesture produces no domain stroke. Input timestamps must be finite, and the engine records them relative to stroke start.

`CanvasARViewModel` coordinates the feature pipeline and owns no duplicate stroke array: its `completedStrokes` and `isDrawing` values are projections of `DrawingEngine`. It gates drawing with the existing typed normal-tracking state, asks `SpatialRaycastService` for each delivered touch position, passes a valid world point to `DrawingEngine`, and directs its event results to the renderer. It cancels and discards an active stroke if input cancels, the app becomes inactive, the Canvas disappears, the session pauses/fails/is interrupted, or tracking becomes limited. It never invents a fallback world coordinate. Completed strokes remain visible only while this non-persistent Canvas session remains active.

`CanvasARViewModel` is also the sole owner of mutable current `BrushSettings` for that Canvas lifetime. `CanvasBrushControlsView` is presentation-only: it receives a value snapshot plus callbacks to select a color or update thickness. It holds no separate drawing color or thickness state. The drawing engine continues to receive `brushSettings.style` only at `beginStroke`, which snapshots the style into the active stroke. A color or thickness change during an active gesture therefore affects the next stroke only; neither the active nor completed stroke is mutated.

The compact bottom `CanvasBrushControlsView` keeps the camera feed visually primary. It provides a live ordinary-SwiftUI preview, five 44-point opaque palette choices (Sky, Red, Orange, Green, Violet), and a 2–20-millimetre slider in 1-millimetre increments. Palette choices are already validated `BrushColor` RGBA values, so no `SwiftUI.Color` or `UIColor` is converted into the persistent domain. The UI converts domain RGBA values only for display; all palette alpha values are fixed at 1. The renderer remains the sole `BrushColor`-to-UIKit/RealityKit material boundary.

Thickness is clamped by `CanvasBrushConfiguration` before `BrushSettings` is updated, preventing the UI from creating zero, negative, non-finite, or out-of-range values. Brush changes call no AR session, AR view, raycast, or renderer lifecycle API; they affect only subsequent drawing-engine stroke starts. The material-backed overlay owns hit testing for its palette and slider, so those interactions do not reach the ARView touch adapter. VoiceOver labels identify each named color and selection state, report the thickness value in millimetres, and identify the brush preview without depending on color alone.

`CanvasHistory` is a framework-independent, bounded value history in `Core/Drawing`. Its current typed `CanvasAction.addStroke(Stroke)` action carries the exact immutable stroke required to reverse or reapply the document change. It has separate undo and redo stacks: recording a completed action appends to undo and clears redo; undo moves an action to redo only after its inverse applies to the document; redo moves it back only after its forward operation applies. This value-based action boundary is intentionally extensible for future delete, move, style-change, and duplicate actions without making the history own an independent stroke collection.

`DrawingEngine.completedStrokes` remains the one authoritative Canvas document state. On successful completion, the Canvas view model records `addStroke` and finalizes the matching runtime representation. Undo removes the exact stable ID from `DrawingEngine`, then requests renderer removal through its ID-keyed registry. Redo restores the same `Stroke` value—preserving its ID, ordered points, timestamps, and `BrushStyle`—then routes it through `renderStroke(_:)` at its original world coordinates. `StrokeRendering` reports success for final rendering, restore rendering, and removal. If a renderer operation cannot be completed, the document remains authoritative, a concise user-visible session hint is shown, and structured diagnostics are logged rather than silently corrupting history.

The Canvas toolbar exposes real, visibly labeled Undo and Redo buttons beside the brush identity. They are disabled whenever their respective stack is empty and while a stroke is active. This prevents history changes from interleaving with active input. The `undoLastStroke()` and `redoLastStroke()` feature APIs are independent of button closures so future keyboard or iPad command routing can call the same operations. Undo/redo only changes the affected stroke representation: it neither restarts `ARSession` nor recreates `ARView` or unrelated scene content.

## Selection and deletion

`CanvasARViewModel` owns the sole runtime selection value, `selectedStrokeID: Stroke.ID?`. It is never added to `Stroke`, `CanvasProject`, or persistence data. The view model also owns the active `CanvasTool`. Entering draw mode cancels an active gesture if necessary and clears selection, avoiding an ambiguous highlighted stroke while drawing. Selection is also cleared on Canvas dismissal, explicit empty-space selection, successful deletion, and any history operation that removes the selected stroke.

Hand hover is separate transient renderer feedback and never establishes authoritative selection. Only a completed hand grab (including a zero-translation grab) sets `selectedStrokeID`.

`CanvasTouchInputAdapter` installs one pan recognizer and one tap recognizer on the stable `ARView`. Pan events are delivered only in draw mode; a single-finger tap is delivered only in select mode, and the tap recognizer requires the pan recognizer to fail. Consequently a drag in select mode neither creates a stroke nor selects it, while a drawing drag never becomes a selection tap. The existing normal-tracking gate is reused before any selection hit test.

Finalized per-stroke meshes generate a collision shape exactly once when the `ModelEntity` is made. On a select tap, `RealityKitStrokeRenderer` calls `ARView.entity(at:)` once, walks the hit entity's parent chain, and resolves the enclosing per-stroke root by object identity in its runtime registry. Thus any segment/model entity maps deterministically to one stable `Stroke.ID`; the Canvas view never guesses ownership from entity names or scans stroke points. Hit targets match finalized tube geometry and may be tuned later only if physical-device testing shows selection is too precise.

Selection feedback is runtime-only. The renderer retains each stroke's original cached `SimpleMaterial` and changes only the selected finalized model to a cached, high-contrast metallic highlight material. Deselecting or choosing another stroke restores the exact original material; no domain `BrushStyle` or saved color changes. The bottom panel states either “Tap a stroke to select it” or “Stroke selected” and exposes the real destructive Delete action, so selection is not indicated by color alone. The panel's controls remain VoiceOver-labeled and are distinct from ARView input.

Deleting a selection removes the exact stroke from `DrawingEngine.completedStrokes`, removes its root from the renderer's ID-keyed registry, clears selection, and records `CanvasAction.deleteStroke(stroke, originalIndex:)`. The captured original document index preserves deterministic ordering on undo. Reversing deletion restores the exact value—including UUID, points, timestamps, creation date, brush style, and world coordinates—at that index and renders it through the normal final-stroke path without reselecting it. Reapplying deletion removes that same UUID. `CanvasAction.addStroke` and `deleteStroke` mix on the same bounded history stacks, so a new action still invalidates redo. Document state remains authoritative if a renderer operation fails: a concise hint and OSLog diagnostic expose the divergence rather than silently hiding it.

`CanvasHistoryConfiguration.standard` retains the most recent 100 actions. This deliberately bounds long-session memory while preserving practical recovery. When full, it discards only the oldest undo record; it never removes the corresponding completed stroke from the Canvas document. Action values use Swift copy-on-write storage, so history retains immutable stroke values without actively copying point buffers unless mutated. Disk-backed history and storage-aware compaction are deferred until the persistence milestone.

`StrokeRenderProcessor` is a pure, deterministic rendering-only stage. It never alters `Stroke` domain data. Its standard configuration first removes duplicate or overly dense points at 0.005 metres, caps the processing path at 1,024 deterministically downsampled points while preserving endpoints, applies a lightweight exponential smoothing pass with a 0.65 input factor while preserving valid first and last points, then linearly interpolates processed pairs toward 0.015-metre segments. Interpolation is capped at 16 segments per input pair and 1,024 total renderable points, preventing runaway allocation. This produces `RenderableStroke`, a runtime value retaining only the stable stroke ID, processed points, and immutable brush style.

`StrokeTubeGeometryBuilder` is also framework-independent. It converts a `RenderableStroke` into validated positions, normals, triangle indices, caps, and an eight-sided tube cross-section. A tube radius is half the validated `BrushStyle.thickness`, so thickness remains a stable world-space property. The RealityKit boundary converts this pure triangle data into a `MeshResource`; domain models never contain a mesh or entity reference.

`StrokeRendering` is a narrow `@MainActor` runtime boundary: begin/update an active stroke, finalize it, render an existing stroke, remove one by ID, resolve a hit entity to an ID, apply runtime-only selection feedback, and clear all content. `RealityKitStrokeRenderer` owns a runtime-only `[Stroke.ID: RenderedStroke]` registry. Each value owns one per-stroke root entity, cached original and selection materials, its selectable finalized model entity when available, and whether it is active or finalized. The registry prevents duplicate rendering, enables deterministic delete/reload behavior, and never becomes persistence data.

During active drawing, each accepted pair is appended as a temporary generated tube segment. This avoids rebuilding the complete mesh on every touch event and remains bounded by the drawing engine's 512-point cap. On completion, the renderer processes the complete raw stroke and replaces all temporary children with one smooth generated tube-mesh `ModelEntity`, retaining the same stroke ID and material. `renderStroke(_:)` uses that same final path for a future repository restore.

All rendered strokes share one world-anchored `AnchorEntity` owned by the renderer. Each stroke has a child root entity beneath it, avoiding one AR/world anchor per stroke. Removing a stroke removes only its root, collision shapes, and registry value; it also clears renderer selection if applicable. Clearing a Canvas removes the shared anchor, registry, and original/highlight material caches. This supports a future spatial-persistence layer without making current domain data depend on AR anchors.

Brush color is converted from the validated `BrushColor` RGBA value only at the RealityKit material boundary. Materials are cached by `BrushColor`; changing future `BrushSettings` cannot mutate an existing stroke's style or material. In DEBUG builds, lightweight structured diagnostics log rendered-stroke count, active temporary segment count, and finalized renderable-point count after meaningful renderer lifecycle changes; Release builds omit these diagnostics.

## Project persistence and restoration

AirCanvas uses an actor-isolated `FileCanvasProjectRepository`, not SwiftData. `CanvasProject` is the stable canvas-document value: UUID identity, normalized name, creation and modification dates, schema version, ordered strokes, and optional `SpatialCanvasState`. The existing immutable Codable domain values preserve IDs, order, schema metadata, points, and styles without introducing SwiftData annotations or storage-model duplication. A document UUID, never its name or renderer position, is the sole authoritative canvas identity.

The local repository owns create, load, save, rename, duplicate, list, and delete operations; SwiftUI library views never access files directly. Documents are atomically encoded as `Application Support/AirCanvas/Projects/project-<canvas UUID>.json`; spatial world maps are separately atomically archived as `Application Support/AirCanvas/Projects/SpatialMaps/world-map-<map UUID>.archive`. This keeps each document's lightweight Codable state separate from opaque AR state while retaining one authoritative document per canvas. The document top-level `schemaVersion` is probed before decoding; unsupported and corrupt documents raise typed repository errors rather than being silently repaired. Deleting a canvas removes its bounded recovery copy before the primary document, then best-effort removes its associated map archive, so a terminated deletion cannot resurrect a canvas from an old backup.

`MyCanvasesView` is the root project library. It presents an accessible empty state, most-recently-modified-first canvas list, New Canvas control, and native Rename, Duplicate, and confirmation-gated Delete actions. New canvases immediately persist under a fresh UUID using a collision-resistant `Untitled Canvas` name. Renaming preserves ID, strokes, and spatial state. Duplicating creates a fresh document UUID and a unique copy name, preserves stroke IDs/styles/order/geometry, and copies any archived world map to a new spatial-map identifier so the duplicate owns its opaque AR state independently. Thumbnails are intentionally a future enhancement: rows currently use reliable metadata (name, modification date, and stroke count) rather than opening an AR session or retaining camera data for previews.

`AppState` owns the process-lifetime repository dependency. `SpatialCanvasAccessView` creates a new canvas only after device capability and camera access succeed, or loads the requested UUID. `MyCanvasesViewModel` is the library feature consumer of repository list/rename/duplicate/delete operations; summaries are deterministically sorted by modification date descending. Opening another canvas constructs a fresh editor runtime so selection, hover, hand grab, transform preview, erase candidate, cursor state, active drawing owner, and bounded undo/redo history cannot cross document IDs. Runtime history intentionally resets when an editor closes; persisted document content remains isolated.

For an active Canvas, project metadata plus `DrawingEngine.completedStrokes` form the document state; `CanvasARViewModel.activeProject` is the validated persistence snapshot rebuilt after completed-stroke, delete, undo, and redo mutations. Each semantic mutation advances `currentDocumentRevision`; `lastPersistedDocumentRevision` advances only after its matching durable repository write, making `dirty = current > persisted` an explicit, testable invariant. The view model debounces meaningful mutations by 750 ms, never raw samples, shows a quiet Saving/Saving changes/Retry Save state, and requests an immediate flush when Canvas disappears or the app backgrounds. A failed in-session save keeps the in-memory document dirty, preserves the last valid file, logs a typed persistence error, and can be retried without restarting.

Milestone 26 wraps each primary JSON in storage-envelope version 1: document revision, canonical encoded payload byte count, and a lightweight FNV-1a integrity checksum. Saves first encode and validate the complete envelope, atomically publish a bounded `project-<UUID>.backup.json` copy of the prior valid primary, then atomically replace the primary through a temporary sibling file; project JSON files use `completeUntilFirstUserAuthentication` protection. `CanvasProjectSaveCoordinator` serializes each canvas ID and `FileCanvasProjectRepository` also rejects an incoming revision older than its persisted revision, so an older asynchronous completion cannot overwrite a newer durable save. Export continues to use a snapshot and never writes through its temporary share file into authoritative storage.

Load recovery is deterministic: validate primary first; only if it is absent or corrupt, validate the one bounded backup; if that succeeds it atomically restores the primary and emits a one-time non-blocking recovery message. A valid primary always wins over an older backup. Unsupported future schemas are surfaced without destructive downgrade. If neither copy validates, that canvas is isolated from the My Canvases scan rather than crashing the library. The library has no fragile separate index: it reconciles metadata by scanning valid primary canvas files, naturally recovering orphaned documents and ignoring stale/missing entries. Thumbnails remain metadata-only/non-authoritative, and an unavailable or corrupt AR world-map archive falls back to the established placement/relocalization guidance while leaving valid stroke content available.

Create, duplicate, and import publish a document only after constructing and validating the complete new `CanvasProject`; a failed publish leaves no library-visible partial primary, and duplicate cleanup removes any newly copied map. The historical direct `CanvasProject` JSON form remains readable as revision zero; it is not replaced until a successful envelope write, so the current schema boundary is migration-safe. Typed repository errors distinguish absent, unsupported, corrupt-primary, corrupt-backup, integrity, spatial, and storage failures. Persistence logging records lifecycle-level save, discard, recovery, reconciliation, and failure events without recording stroke payloads or camera/hand data.

Opening a saved project seeds `DrawingEngine` with persisted strokes and asks `StrokeRenderer` to reconstruct each through its normal final rendering path exactly once. Selection, active gestures, RealityKit entities, AR frames, camera data, and history are never stored. Persisted coordinates are faithfully reconstructed in the current AR world coordinate system, but this milestone does not restore the prior AR world origin, anchors, or room alignment; a later spatial-persistence milestone must address that explicitly.

## Tracking, interruption, failure, and lifecycle behavior

## Spatial persistence and relocalization

AirCanvas targets iOS 17 and uses the supported `ARWorldMap` mechanism with `ARWorldTrackingConfiguration.initialWorldMap` for local AR-world restoration. `SpatialCanvasState` is a small Codable domain metadata value attached optionally to `CanvasProject`; it records only a map identifier, map schema version, capture time, and mapping quality. It contains no ARKit object or file path. The large map is securely archived with `NSKeyedArchiver` and stored as a separate atomically written file under Application Support/AirCanvas/Projects/SpatialMaps.

`ARSessionService` remains the sole `ARSession` owner. It accepts an initial `ARWorldMap` before starting and configures it only when reopening a spatial project. `ARFrame.WorldMappingStatus` is mapped to the application-facing `SpatialMappingQuality`; normal project data always saves, while a spatial map is requested only when status is `mapped`. A world-map write completes before project JSON is updated to reference it; a failed replacement preserves the prior reference. Old map files are removed only after the new project metadata write succeeds.

Opening a project with a spatial reference reads and securely decodes its map before the session starts. `SpatialRelocalizationState` is a typed state machine (`none`, `preparing`, `scanning`, `localized`, `failed`, `fallback`). Stored strokes are deferred until ARKit reports normal tracking following relocalization, so they are not shown at arbitrary coordinates while scanning. After a 45-second guidance interval without success, the UI offers Keep Scanning, Open Without Spatial Alignment, or Return Home rather than implying that a timer proves failure. If the map is missing or corrupt, the user can explicitly open without spatial alignment; the original map reference is preserved and is not overwritten by that fallback session. Projects created before spatial metadata remain valid and render under the documented non-relocalized behavior.

Deleting a project removes its JSON first and then best-effort removes its associated map file, logging any post-delete cleanup failure without resurrecting the project. No camera frames, AR frames, RealityKit entities, selection state, or gesture state are persisted. Actual relocalization quality must be confirmed on physical hardware; simulator builds cannot validate it.

## Native document transfer and image export

Milestone 25 adds a portable AirCanvas transfer boundary without exposing repository files. `AirCanvasDocumentPackage` is a versioned Codable `.aircanvas` payload registered as `com.aircanvas.document` (`public.data`), with format identifier and version, source-canvas UUID metadata, name, source creation/export dates, ordered `Stroke` values, coordinate-space metadata, a source geometry reference point, and a small future-compatible metadata dictionary. It deliberately excludes local project IDs, repository paths, selection/history/runtime state, camera data, and `ARWorldMap` archives.

The current package coordinate model is `arWorldReferenceV1`: stroke points remain exact source AR-world-axis values and an all-point centroid is carried as a reference. On import, `AirCanvasDocumentImporter` translates the complete geometry as one rigid offset from that source reference to a deterministic fresh-session local reference `(0, -0.2, -1.0)`. Thus relative geometry, IDs, styles, point order, and transformed shape survive, while an imported canvas never silently claims alignment with the exporter’s physical room. Imported content opens as a normal no-world-map canvas and can be repositioned with the established Select-mode controls. Environment-specific relocalization state is intentionally not portable.

`AirCanvasDocumentExporter` builds and validates a package from the immediate authoritative `CanvasARViewModel` snapshot, writes a collision-safe temporary `.aircanvas` file atomically, and hands only that temporary copy to the native system Share Sheet. This captures changes before the normal autosave debounce while independently requesting a normal save; it never shares an authoritative Application Support file. The Share Sheet supplies Files, AirDrop, Messages, Mail, and installed destinations without app-specific integrations. Temporary exports are removed after the share flow completes.

`MyCanvasesView` imports with the native document picker, uses security-scoped URL access only for the picker-provided read, releases that access immediately, then routes validated portable content through `CanvasProjectRepository.importProject`. The repository assigns a fresh local canvas UUID and collision-safe local name, writes the new document atomically, and keeps imported content isolated from its source and all other canvases. Invalid format identifiers, unsupported versions, malformed data, duplicate stroke IDs, non-finite or out-of-range geometry, invalid style values, and resource-limit violations fail safely with concise user-facing import feedback.

Limits are centralized: 25 MiB transfer files, 10,000 strokes, 1,024 points per stroke, 200,000 total points, 120-character names, 16 bounded metadata entries, 10 km coordinate magnitude, and 100 mm maximum stroke thickness. These limits bound decoder work and prevent malformed files from becoming unbounded document allocations.

`CanvasImageExporter` produces a deterministic 2048×2048 transparent PNG from document strokes only—never a UI screenshot. It selects the two world axes with the largest artwork extent (stable X/Y/Z tie-breaking), uses orthographic projection, centers the artwork with 8% padding, preserves stroke ordering/color and relative thickness, and omits cursor, toolbars, selection/highlight, hand, and debug state. Empty canvases produce a valid blank transparent PNG. Image sharing reuses the same temporary-file Share Sheet path. The image is a stable document illustration rather than a camera-pose-dependent AR screenshot.

## Vision hand-pose detection

`Core/Vision` is a separate on-device subsystem. `ARSessionService` remains the single camera owner and forwards only transient `ARCameraFrame` values from its existing `ARSessionDelegate` frame callback. `HandTrackingCoordinator` consumes those frames on a serial user-initiated queue; it accepts at most 15 frames per second and drops frames while a request is active, preventing stale work from accumulating behind AR rendering.

## Runtime performance and long-session policy

Milestone 27 keeps ARKit at its required tracking cadence while making Vision explicitly bounded: `HandTrackingCoordinator` allows one request in flight and retains at most one newest pending `CVPixelBuffer`. Older busy-frame candidates are replaced, never queued indefinitely. Each frame has a generation and sequence; disabling hand tracking clears pending work, and delivery rechecks both values on the MainActor so stale results cannot move a re-entering cursor backward. The scheduler’s normal ceiling is 15 Hz, with a centralized policy reducing only Vision work to 12 Hz for serious thermal state or Low Power Mode and 8 Hz for critical thermal state. AR world tracking, touch fallback, and document editing remain available; policy transitions are logged without per-frame user alerts.

`ARSessionService` forwards camera frames through a small lock-protected bridge directly to that bounded coordinator instead of creating a MainActor task for every AR frame. World-mapping changes are published only when their typed value changes. Pixel buffers are passed directly to `VNImageRequestHandler` and retained only by the one active or one pending Vision request; no UIImage, CIImage, CGImage, camera-frame history, or camera payload logging is introduced. The AR configuration remains intentionally minimal: horizontal/vertical plane detection for established raycasts, with no scene reconstruction, semantics, mesh generation, or person segmentation.

The cursor raycasts once from the existing stabilized display point and shares that result with Draw, Select, and Erase routing. It skips unchanged display points below a centralized 0.5-point epsilon, invalid/lost hands, unusable tracking, and inactive Canvas states. `SpatialStrokeHitTester` keeps exact point-to-segment geometry authoritative but first rejects candidates whose derived non-persisted world bounds are outside the active radius; it allocates no temporary point-position array per tested stroke. Stroke point density remains governed by the existing 0.01-metre `DrawingEngine` spacing rule—no post-stroke simplification was added because measured domain point caps already bound active strokes without changing physically validated line quality.

Renderer work remains incremental: active strokes append only accepted segments, finalized/reloaded strokes build one mesh, materials are cached by immutable color, and `clear()` releases all canvas entities when the editor closes or switches documents. A memory warning drops only rebuildable material caches; `CanvasProject`, Stroke data, active document state, and durable-save state are never treated as cache. Canvas backgrounding uses the existing cancellation and revision-aware save flush, disables hand processing through the Canvas lifecycle, and foregrounding reuses the single existing AR session/coordinator without registering duplicate observers or loops. `HandTrackingCoordinator` unregisters its thermal/Low-Power observers on deinitialization; Canvas removes its memory-warning observer on deinitialization.

DEBUG instrumentation uses the `performance` OSLog category and Vision signposts around Vision requests. It records bounded Vision scheduling counters and mean latency, finalized/restored stroke-render durations and point counts, autosave duration/revision, canvas preparation duration, material-cache releases, and thermal-policy/memory-warning events. These are local diagnostics only; no analytics, camera contents, hand observations, or canvas payloads are collected. Deterministic DEBUG test fixtures create 100-, 500-, and 1,000-stroke canvases with eight points per stroke for load and hit-test profiling; physical Instruments runs provide the authoritative FPS, thermal, energy, and memory measurements.

`HandPoseDetector` owns a one-hand `VNDetectHumanHandPoseRequest`. It receives a pixel buffer and image orientation and returns no more than a typed `HandTrackingState`: `noHand`, `unreliable`, or a `HandPose` containing confidence-bearing normalized-image landmarks for index tip, thumb tip, and optional wrist. `HandLandmark` validates that normalized coordinates and confidence values are finite and within zero-to-one bounds. The centralized confidence minimum is 0.65; both required tips must meet it before a pose is considered detected.

Vision runs off the main actor. The coordinator protects its enable state and throttle gate with a lock, clears its gate and publishes no stale landmarks when Canvas becomes inactive, and publishes only the latest result back to the main-actor Canvas model. The Canvas shows a quiet accessible status label; detection changes are not announced repeatedly. Frames and landmarks are neither persisted nor uploaded. The current rear-camera orientation is `.right`, matching the portrait Canvas pipeline; rotation-aware interaction mapping is deliberately deferred with normalized-to-screen conversion.

## Fingertip cursor

`FingertipCursorModel` is transient SwiftUI-overlay state, separate from drawing and persistence. It consumes only high-confidence index-tip landmarks, converts Vision lower-left normalized image coordinates into the actual top-left Canvas viewport, and renders a non-hit-testable 2D cursor. `PointSmoother` applies a configurable exponential moving average (0.35 factor) and resets immediately when tracking is lost, so a re-entering hand never interpolates from a stale location. The current portrait path uses the same `.right` Vision orientation as detection; ARKit display-transform/cropping calibration and landscape support require physical-device validation before being expanded.

## Pinch classification

`PinchGestureClassifier` is a framework-independent value state machine in `Core/Vision`. Existing `HandTrackingState.detected(HandPose)` values feed it after Vision confidence validation; it has no ARKit, RealityKit, SwiftUI, or drawing dependency. It uses the Euclidean distance between normalized index-tip and thumb-tip coordinates. The configuration uses a 0.09 entry threshold, a larger 0.14 release threshold, 0.12-second entry/release confirmations, and a 0.18-second loss grace period. This hysteresis keeps a confirmed pinch active between the thresholds.

Its typed progression is `idle`, `pinchCandidate`, `pinching`, and `releaseCandidate`. It emits `.began` once when a candidate remains valid through confirmation, `.ended` once after confirmed release, and `.cancelled` after prolonged loss while active. Invalid, unreliable, or missing hands cannot begin a pinch; candidate loss resets immediately, while active loss is allowed only for the grace period. Canvas owns the current informational `pinchGestureState`, resets it on backgrounding and Canvas dismissal, and uses it for cursor feedback. The classifier itself has no ARKit, rendering, selection, deletion, or drawing dependency.

## Spatial fingertip cursor

The stabilized 2D fingertip display point reuses `SpatialRaycastService`'s existing-plane-geometry then estimated-plane strategy. `SpatialFingertipState` is transient (`unavailable`, `searching`, or `tracked` with a current-AR-world `SIMD3<Float>`). Failed or non-finite raycasts never fabricate depth and hide the cursor. `SpatialFingertipProcessor` rejects a consecutive world-point jump above 0.45 metres before applying a 0.35 world-space exponential smoother; loss, lifecycle changes, and re-entry reset both history and smoothing.

`RealityKitSceneController` owns one reusable sphere cursor entity and updates only its transform/material. It hides on missing hand, raycast failure, inactive Canvas, or tracking loss. Confirmed pinch changes its material only. The spatial-cursor pipeline itself does not call the drawing engine; the separate hand-input adapter below consumes its validated state. Raycasting is shared with touch, and saved-project relocalization must be normal before interaction is usable.

## Hand drawing input

Milestone 19 adds `DrawingInputSource` as the single runtime owner of an in-progress `DrawingEngine` stroke: `none`, `touch`, or `hand`. It is transient Canvas state, never project data. The established touch adapter claims `.touch` only after `DrawingEngine.beginStroke` succeeds and releases it on normal end, cancellation, tool changes, tracking failure, lifecycle reset, and Canvas dismissal.

`CanvasARViewModel` is the hand-input adapter. It consumes the existing Vision hand result and `PinchGestureEvent`, plus only the already stabilized `SpatialFingertipState.tracked` world coordinate. On `.began`, it starts the *same* `DrawingEngine` stroke only when the Draw tool owns no other input, AR tracking is usable, and saved-project relocalization is either localized or explicitly in fallback. A pinch that begins without a valid world point is deliberately ignored for its entire active duration; release and a new pinch are required. While `.hand` owns the engine and the pinch remains confirmed, new tracked positions call the ordinary append API, preserving the engine's spacing, point validation, brush snapshot, and rendering path.

`.ended` uses the normal end path, so the resulting ordinary `Stroke` enters `CanvasHistory` as `AddStroke`, finalizes through `StrokeRenderer`, updates the active project, and schedules the existing autosave. `.cancelled`, hand loss, AR tracking loss, relocalization becoming unsuitable, an app/Canvas lifecycle reset, or a switch away from Draw cancel the in-progress stroke and release ownership. No stale hand stroke resumes after recovery. Spatial/raycast loss never fabricates or appends a point. Touch and hand input are mutually exclusive, but touch remains a permanent full-featured fallback.

This end-to-end path has been validated on a real iPhone: the 3D fingertip cursor, hand tracking, pinch/release recognition, spatial stroke creation, separate interactions, hand-loss recovery, and touch fallback all worked through the production Camera → Vision → fingertip → pinch → AR raycast → `DrawingEngine` → spatial-stroke pipeline.

Hand input supports Draw-mode stroke creation and Select-mode hover/grab manipulation. It does not perform destructive hand gestures, erase, gesture undo/redo, or any two-hand interaction. The hand-input adapter owns neither an AR session, Vision request, renderer, history system, nor persistence implementation; it is solely an input translation layer into the existing Canvas document APIs.

## Hand spatial stroke manipulation

`StrokeTransformer` is a pure Foundation/simd component shared by future input paths. It computes a deterministic centroid pivot from all valid stroke points, scales geometry uniformly around that pivot (initial limits 0.25×–4×), and rotates around the world-up (Y) axis in radians. Brush thickness and all stroke metadata remain unchanged. Every preview is derived from the immutable original snapshot plus current parameters; no cumulative floating-point transforms are applied.

`CanvasARViewModel` owns transient `StrokeTransformState` and exposes accessible Select-mode Scale (0.25×–4×) and Rotate (−180°…+180°) sliders. A slider begins a snapshot transaction, updates renderer preview geometry, and commits one existing snapshot-based `moveStroke` history action when editing ends. Cancel/reset restores the original render without document mutation. Controls are unavailable in Draw mode or during an active hand grab, and Delete is gated while a transform is active. Committed replacements preserve Stroke ID, selection, style, ordering, persistence, autosave, and exact Undo/Redo behavior; no two-hand transform gesture is implemented.

Real-iPhone validation passed for stable centroid pivots, uniform scaling, world-up rotation, live preview, one semantic history operation per transform, exact undo/redo, move→scale→rotate→delete ordering, transformed-geometry persistence through relocalization, repeated-transform stability, renderer-entity reuse, and all Milestone 19–21 plus touch workflows.

`SpatialStrokeHitTester` is a framework-independent world-space polyline hit tester. It measures the fingertip’s minimum distance to every stroke segment, including zero-length segments, and uses a centralized initial 0.08-metre selection radius. It rejects non-finite inputs and geometry; when several candidates are equally close it retains the first document-order stroke, preventing jittery random selection. Touch selection remains RealityKit entity hit testing and continues to operate independently.

`CanvasARViewModel` owns the transient typed `HandSelectionState`: `idle`, `hovering(Stroke.ID)`, or `grabbed(strokeID, initialHandPosition, originalStroke, translation)`. In Select mode, accepted world-space fingertip updates perform hover lookup and use a separate transient hover highlight. A confirmed pinch grabs only a currently hovered stroke, retaining an immutable original `Stroke`; a pinch with no target has no effect. On release, including a zero-translation grab, the stroke becomes the authoritative selected ID. The Draw tool preserves Milestone 19 behavior, where a pinch drives normal hand drawing instead.

While grabbed, the current translation is always `currentHandPosition - initialHandPosition`. Preview rendering applies that translation only to the existing stroke root entity, so no duplicate geometry, scene rebuild, document mutation, history entry, or autosave is produced per frame. The final stroke is always derived from `originalStroke + finalTranslation`, preserving stable Stroke ID, style, point order, timestamps, and creation metadata without cumulative transform drift. On release, the moved snapshot replaces the document stroke in place, the renderer rebuilds it once at the committed coordinates, and `CanvasAction.moveStroke(before:after:)` records one undoable operation. Undo and redo restore exact snapshots; the ordinary document-change path then drives autosave and existing project/spatial restoration.

Pinch cancellation, prolonged hand loss, AR tracking or relocalization loss, lifecycle reset, Canvas dismissal, or a tool change restore the preview root to zero translation, retain the original document stroke, and commit no move action. Temporary raycast loss holds the last preview; only already accepted, jump-filtered spatial points can update it. `DrawingInputSource` still exclusively owns active drawing strokes; a grab is a separate Select-mode interaction and cannot coexist with touch/hand drawing. Touch drawing, touch selection, and touch deletion remain available. Hand deletion, rotation, scaling, and two-hand transforms are intentionally not implemented.

## Explicit hand-selected deletion

Milestone 21 keeps deletion destructive only through the existing explicit Delete control. A completed hand grab converges on the same `selectedStrokeID` used by touch selection; hover, pinch candidate, cursor movement, hand/tracking loss, lifecycle reset, and tool changes cannot delete or create history. The Delete button removes that stable ID through the normal document, renderer, history, and autosave path. One delete records one snapshot-based `deleteStroke` action, so Undo restores the exact moved or original stroke and Redo removes that same ID again. Nil or stale selections are harmless and clear safely. No destructive hand gesture is implemented; touch selection/delete remains the accessible fallback.

Physical-device validation passed on a real iPhone: hover remained non-destructive; pinch/release selected strokes with or without movement; explicit Delete removed only the selected ID; empty-space pinch, hand loss, tracking loss, and lifecycle changes never deleted; exact delete and move-then-delete Undo/Redo ordering held; Draw-mode pinch drawing, Milestone 20 manipulation, touch workflows, autosave, and spatial relocalization remained functional without duplicate strokes or history corruption.

## Spatial eraser

Milestone 23 adds an explicit `CanvasTool.erase` mode. `EraseInteractionState` is transient and contains only `idle` or a stable-ID hover candidate. Accepted world-space fingertips reuse `SpatialStrokeHitTester` with a centralized 0.10-metre erase radius; hover changes runtime feedback only. A confirmed pinch deletes the captured candidate through the same stable-ID document, renderer, `deleteStroke` history, autosave, and persistence path as explicit Delete. The candidate is cleared before deletion, so one held pinch deletes at most one stroke; release and a new pinch are required for another erase. Draw and Select modes retain their existing pinch semantics. Tracking, hand, lifecycle, relocalization, and tool changes clear the candidate without mutating content; touch Delete remains the accessible fallback.

`ARTrackingState` maps `ARCamera.TrackingState` into initializing, normal, limited with a typed limitation, or unavailable. Limited states generate concise product guidance: move more slowly, point toward a textured area, or wait while relocalizing. Normal tracking has no overlay.

`ARSessionState` and `ARSessionStateReducer` translate lifecycle events into idle, running, interrupted, or typed failed state. `ARSessionDelegate` methods are nonisolated adapters that extract typed Sendable state and hand it to the main-actor service, keeping callbacks short and observable Canvas state safe.

During interruption, the Canvas shows a quiet status and logs the transition. When interruption ends, the service resets tracking and existing anchors only when the Canvas still demands a running session. A failure is logged as a structured AR diagnostic, shown as a Canvas-specific recoverable state, and offers one explicit retry or Return Home; there is no retry loop.

`CanvasARViewModel` separately tracks Canvas visibility and app activity. It requests a running session only while both are true; backgrounding, inactivation, or navigation away pauses the session. Returning active starts it once. This coordination is outside SwiftUI view bodies.

## Performance architecture and physical profiling

AirCanvas uses one production AR frame path: `ARSessionService` forwards frames directly to `HandTrackingCoordinator`, whose `VisionFrameScheduler` allows one request in flight and retains only the latest pending frame. Each request carries generation and sequence state, so disabled or stale results cannot overwrite newer hand state. The normal Vision cap is 15 Hz; serious thermal state and Low Power Mode cap it at 12 Hz, and critical thermal state at 8 Hz. Thermal and Low Power notifications dynamically refresh that policy; inactive canvas lifecycle disables Vision, clears the pending frame, resets interaction state, pauses AR demand, and preserves the existing save flush.

Spatial cursor raycasts are gated by valid accepted fingertip input and a display-space epsilon, and their single result feeds drawing, selection, and erase routing. `SpatialStrokeHitTester` uses deterministic per-stroke bounds prefiltering before exact segment distance; test-only deterministic fixtures cover 100, 500, and 1,000 strokes. `RealityKitStrokeRenderer` owns one root per Stroke, removes roots on delete/clear, replaces active previews with one finalized model, caches rebuildable materials, and purges only derived material caches on memory warning. Canvas closure clears renderer entities, cancels relocalization/autosave delay work, and releases session demand; `HandTrackingCoordinator` removes thermal/power observers in `deinit`. There are no Timer, CADisplayLink, Combine, or parallel scheduler lifetimes in the production path.

DEBUG profiling reuses sparse `OSSignposter` Vision intervals, hand diagnostics (submitted, started, coalesced, cadence-dropped, published, and average request duration), renderer diagnostic counts, canvas-load/finalization/save duration logs, and deterministic test fixtures. These local regression diagnostics contain no user canvas payload, camera contents, or persisted telemetry. Autosave remains semantic-mutation-only and 750 ms debounced, with revision-aware serialized writes, stale-save rejection, atomic persistence, backup recovery, and lifecycle flush taking precedence over small performance gains. Milestone 30 physically exercised Time Profiler, Allocations, leak inspection, Memory Graph, Low Power Mode, thermal transitions, background/foreground cleanup, large-canvas workloads, and a sustained 30+ minute mixed AR editing session. No production-blocking CPU hotspot, unbounded application-memory growth, leak, stale runtime accumulation, crash, or progressive user-visible slowdown was identified; precise CPU, memory, FPS, battery, and energy figures were not recorded and are not claimed.

The physically validated production flow is Camera/AR frame → bounded production Vision scheduler → stale-result protection → `HandTrackingState` → spatial fingertip processing → gated/coalesced raycast → interaction routing → DrawingEngine/editing domain → StrokeRenderer. The one-in-flight/latest-pending policy, thermal-aware cadence, Low Power Mode adaptation, background cleanup, renderer entity/cache cleanup, and durability-preserving autosave coalescing remained functional throughout hand/touch drawing, selection, hand/touch translation, transforms, erase/delete, Undo/Redo, canvas switching, persistence, and lifecycle transitions. Performance remains hardware- and environment-dependent: very large documents increase rendering/hit-test cost, ARKit/Vision vary with lighting and tracking conditions, iOS controls thermal throttling, and sustained camera/AR use consumes more battery than non-camera workflows.
